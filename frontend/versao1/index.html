Orientações e Regras de Validação
1. Cadastro de Itens & Schema

O campo cClassTrib deve ser mandatório. O sistema deve validar ativamente a compatibilidade NCM x Classificação antes de gerar o XML da venda.

2. Alíquota de Teste (Fase 2026)

As operações simuladas no PDV devem utilizar a alíquota total temporária de 1% (sendo 0,9% para a CBS e 0,1% para o IBS). A alíquota padrão estimada de 26,5% deve ficar em modo latente.

3. Validação XML (Nota Técnica 2025.002)
  • Rejeição 530: Tag cClassTrib ausente no nó de tributação do item.
  • Rejeição 999: Incompatibilidade cadastral ou de regras detectada.

1. Engenharia do Projeto

Esta Prova de Conceito (PoC) foi projetada sob o princípio de automação fiscal baseada em dados puros (Zero Hardcode). O sistema não utiliza condicionais estáticas para decidir impostos. Toda a inteligência tributária foi delegada para relacionamentos matemáticos nativos executados dentro do banco de dados local.

2. Fontes de Dados Externas

  • Planilha IVA Dual (SEFAZ): Fornece a matriz de flags booleanas de blocos fiscais (ex: ind_gIBSCBSMono) vinculadas a cada CST/cClassTrib da LC 214/2025.
  • Tabela de NCM do Fisco: Associa o NCM de 8 dígitos do produto ao código estrutural do cClassTrib.
  • Arquivo Bruto do IBPT: Fornece as alíquotas estimadas de carga para a Lei da Transparência (12.741/12) vinculadas estritamente por NCM.
